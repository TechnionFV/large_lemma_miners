### Module Behavior and Property Meaning:

This SystemVerilog module models a simple arithmetic loop that repeatedly updates two signed integers `x` and `y` based on a termination condition. The loop continues until `x` becomes non-negative, and a formal property checks that a specific relation holds between the updated values at the end of execution.

Parameters and Inputs:
- `WIDTH`: Bit-width of the signed variables (default 32 bits).
- `clk`: Clock signal.
- `rst`: Reset signal.
- `y_raw`: Signed input value (not used in this implementation; `y` is hardcoded to `-2`).

Internal Variables:
- `x`: Starts at `-5` and is incremented by `y` in each iteration.
- `y`: Starts at `-2` and is incremented by 1 in each iteration.
- `y_init`: Stores the initial value of `y` (always `-2` here).
- `c`: Counts the number of loop iterations.
- `state`: Finite state machine with two states: `LOOP` and `DONE`.

State Machine:
- `LOOP`: Runs while `x < 0`.
  - In each iteration:
    - `x` is incremented by the current value of `y`.
    - `y` is incremented by 1.
    - `c` is incremented by 1.
  - When `x >= 0`, transitions to `DONE`.
- `DONE`: Terminal state with no further updates.

Behavior on Reset:
- On `rst`:
  - `x` is set to `-5`.
  - `y` and `y_init` are set to `-2`.
  - `c` is set to 0.
  - FSM state is initialized to `LOOP`.

Property Assertion:
- The module includes a property `prop` that asserts:
  "At every rising clock edge, unless in reset, if the FSM is in `DONE` state, then `y > 0` must hold."
- This checks that once the loop terminates, the value of `y` has become positive.


### Proposed Lemmas:
We propose four lemmas that collectively form a proof establishing the property.


Lemma 1:
  On every rising clock edge, unless in reset, it holds that `x <= -5 + y * c`.
This holds because `x` is initialized to `-5` and, in each iteration of the loop, is incremented by the current value of `y`. At the same time, `y` increases by 1 on each iteration. Since earlier values of `y` were smaller, the cumulative sum of increments to `x` is less than or equal to `c` times the current value of `y`. Moreover, Lemma 2 will establish that there is no risk of overflow for `x`, `y` and `c`. Thus, `x <= -5 + y * c` always holds.


Lemma 2:
  On every rising clock edge, unless in reset, it holds that `(c >= 0 && c <= 100 && y <= 100 && y >= -2)`.
This lemma provides upper and lower bounds on the values of `c` and `y`, ensuring they remain within a safe, non-overflowing range throughout execution.
By Lemma 1, `x <= -5 + y * c`, so these bounds also imply that `x` cannot overflow.
The bounds are derived from a conservative estimate of the maximum number of iterations the system can spend in the `LOOP` state.


Lemma 3:
  On every rising clock edge, unless in reset, it holds that if `y <= 0`, then `x < 0`.
Justification:
This lemma follows directly from Lemmas 1 and 2:
- Lemma 2 guarantees that there is no overflow or underflow in computing expressions like `-5 + y * c`, `y * c` or `x`,
and it ensures that `c >= 0`.
- Lemma 1 gives the bound `x <= -5 + y * c`.
- Now, if `y <= 0` and `c >= 0`, then `y * c <= 0`, and therefore `x <= -5 + y * c < 0`, since `-5 + (nonpositive value)` is strictly less than zero.
Thus, under the condition `y <= 0`, `x` must be strictly negative, as claimed.


Lemma 4:
  On every rising clock edge, unless in reset, it holds that if `x < 0` then `state != DONE`.
This lemma is 1-inductive and thus easily provable:
- Base case (after reset):
`state` is initialized to `LOOP`, so `state != DONE`, and the consequent holds regardless of the value of `x`.
- Inductive step - assume the lemma holds in the current state:
  - If `state == LOOP`:
    - If `x < 0`, the FSM remains in `LOOP`, so `state != DONE` holds in the next state.
    - If `x >= 0`, `x` is not updated in the current cycle and the FSM transitions to `DONE`. Therefore, in the next state `x >= 0` still holds, so the antecedent (`x < 0`) is false, and the implication holds.
  - If `state == DONE`, no variables are updated, so if the lemma holds in the current state, it continues to hold in the next state as well.


Lemma 3 and Lemma 4 imply together the property:
- Assume `state == DONE`. We show that `y > 0`.
- By the contrapositive of Lemma 4:
  Since `state == DONE`, it cannot be the case that `x < 0`. Therefore, `x >= 0`.
- Now, apply the contrapositive of Lemma 3:
  Since `x < 0` does not hold, Lemma 3 implies that `y <= 0` cannot hold either.
  Therefore, `y > 0`.
Thus, under the assumption that `state == DONE`, it follows that `y > 0`, as required.
